## 👤 About Me

I got into computers as a teenager — building websites for fun, doing computer repair out of the house. I figured out early that if something was broken, I wanted to be the one to fix it. That applied to machines and eventually to kitchens too.

I spent a decade cooking professionally — every station, every shift type, every kind of service. Not as a hobby. As a job, in real restaurants, with real pressure. Somewhere along the way I looked at the software running those places and thought: *this is embarrassing.* Clunky systems that cost a fortune, built by people who'd never worked a line. Toast and Square weren't built by cooks. I was.

So I went back to coding — not to switch careers, but to bridge the gap between the two things I actually know. Everything I build lives at that intersection. The kitchen taught me how to work under pressure, eliminate waste, and never ship something half-done. The tech background taught me how to think in systems. Together, those two things make me build differently than most food-tech developers.

I'm currently working toward opening **Half Baked Café & Bakehouse** in 2027. Everything I'm building is going to run in that kitchen on day one — that's not a pitch, that's the plan.

### 🌐 CulinaryOS

<img src="https://img.shields.io/badge/TypeScript-3178C6?style=for-the-badge&logo=typescript&logoColor=white" />
<img src="https://img.shields.io/badge/React_18-20232A?style=for-the-badge&logo=react&logoColor=61DAFB" />

**The open-source restaurant operating system.**

Every system a restaurant needs — point of sale, kitchen display, inventory, staff scheduling, online ordering, reservations, reporting — in one connected platform. Self-host it for free or use the managed version. Built on the same model as open-source tools like Ghost and Cal.com: you own your data, you own your setup.

<details>
<summary><b>▶ Full details — architecture, story, who it's for</b></summary>

<br/>

**The story behind it**

Every restaurant I worked in ran on expensive, disconnected systems. The POS didn't talk to the kitchen display. The scheduling was done in a spreadsheet. Inventory was a clipboard. And every vendor wanted $300/month for software that crashed on a busy Saturday. The tools built for restaurants were mostly built by people who had never actually run one. I have. So I'm building the version that doesn't suck — and making it open source, because an operator shouldn't need a software contract to run their kitchen.

**For anyone:**
Imagine every system a restaurant needs living in one place — from the moment a customer places an order to the moment it's fired on the line, tracked in inventory, and settled on a report at the end of the night. That's CulinaryOS. Runs in any browser. No special hardware required. You can run it yourself for free or pay for a hosted version with support.

**For developers:**
Next.js 14 PWA with a Hono/Node.js API gateway, architected as an MCP orchestration hub. Each domain is an independently deployable MCP tool server — POS, KDS, inventory, scheduling, ordering, reservations, reporting. Turborepo monorepo. Supabase for Postgres, Auth, Realtime, Storage, and Edge Functions. Stripe Elements + Stripe Terminal for payments. shadcn/ui + Tailwind. The Ratio Blueprint Engine (`@culinaryos/ratio-engine`) is the core differentiator — recipes stored as ratios, not weights, enabling true AI-powered scaling and food cost projection.

**Who it's for:**
Restaurant owners. Kitchen managers. Food service operators at any scale — from a single café to a multi-location group.

**Deployment model:**
- **Self-hosted (free):** Fork the repo, run `docker-compose up`, connect your own Supabase. Full features.
- **Hosted SaaS (paid):** Managed by me. Includes updates, support, monitoring, and hardware agent download.
- **Enterprise:** Custom contracts, white-label, dedicated infrastructure.

```
pnpm Monorepo (Turborepo)
├── apps/pos           React 18 · Vite  — tablet POS (order entry, table map, modifiers, splits)
├── apps/kds           React 18 · Vite  — real-time kitchen display (Supabase Realtime)
├── apps/admin         React 18 · Vite  — back office, scheduling, staff, settings
├── apps/web           React 18 · Vite  — public storefront + online ordering + reservations
├── apps/ops           React 18 · Vite  — P&L, food cost %, labor %, AI anomaly alerts
├── services/api       Hono · Node 20   — single API gateway (:3000)
├── mcp/
│   ├── pos-mcp              fire_order · void_item · split_check · get_open_tickets
│   ├── kds-mcp              bump_ticket · route_station · get_active_tickets · fire_course
│   ├── inventory-mcp        check_par · log_waste · create_purchase_order · get_vendors
│   ├── scheduling-mcp       build_schedule · project_labor_cost · flag_overtime · clock_in
│   ├── ordering-mcp         get_online_orders · update_prep_time · mark_ready · inject_to_kds
│   ├── reservations-mcp     book_table · get_covers_by_shift · get_waitlist · release_table
│   └── culinaryos-mcp       Master router — routes all sub-servers + external MCPs
└── packages/
    ├── @culinaryos/ratio-engine   ← THE differentiator (pure TS, zero deps)
    ├── @culinaryos/db             Supabase client + generated types
    ├── @culinaryos/event-bus      Typed in-process event emitter
    ├── @culinaryos/ui             Shared React components (shadcn base)
    └── @culinaryos/config         Env schema, feature flags
```

> **Ratio Blueprint Engine** — Every other POS stores `bread_flour: 500g`. CulinaryOS stores `bread_flour: 100%` (baker's percentage) and understands the *relationship*. True prep scaling, food cost projection, and AI menu assistance that no other system does.

**Your kitchen's second brain.**

Recipe management, meal planning, pantry tracking, shopping lists, and nutrition — all in one app. Built the way a professional cook would actually design it, not the way a product team who eats takeout would.

<details>
<summary><b>▶ Full details — architecture, story, who it's for</b></summary>

<br/>

**The story behind it**

This one started as RecipeOS — an Android app I was building to manage my own recipe library the way I actually think about recipes. Not just a list of ingredients. The ratios, the scaling logic, the mise en place, the prep workflow. Then PrepFlow got folded in. Eventually both became KitchenKit — a full PWA that works on any device, no install required. The goal was simple: build the tool I'd actually want open on my phone in a kitchen.

**For anyone:**
KitchenKit is where you keep your recipes, plan your meals for the week, track what's in your pantry, and get a shopping list auto-built from what you're missing. If you cook seriously — whether at home, as a caterer, or as a personal chef — it handles the organizational side so you can focus on the actual cooking. Works on your phone, tablet, or computer.

**For developers:**
Next.js 14 PWA. TypeScript throughout. Supabase for all data — recipes, meal plans, pantry, shopping lists — secured with Row-Level Security. MCP live: `kitchenkit-mcp` exposes `search_recipes`, `get_recipe`, `add_to_meal_plan`, `get_pantry`, `get_shopping_list` for AI agent workflows. Standalone deployment — no CulinaryOS account required. Merges RecipeOS (archived) + PrepFlow (Notion-only, never a standalone repo).

**Who it's for:**
Home cooks who take it seriously. Meal preppers. Caterers. Personal chefs. Culinary students building a recipe library. Anyone who has ever lost a recipe they wrote on a piece of paper.

**Back-of-house business intelligence.**

Labor cost, food cost, waste tracking, vendor management, purchase orders — the business side of running a kitchen, in a dashboard that actually makes sense.

<details>
<summary><b>▶ Full details — architecture, story, who it's for</b></summary>

<br/>

**The story behind it**

This started as RestRevive-AI — a tool for restaurant operators who needed an AI-assisted operations audit. The more I built, the more I realized the real problem wasn't the audit. It was that nobody had good visibility into their numbers on a day-to-day basis. Food cost was figured out monthly, if at all. Labor was managed by gut feel. Waste wasn't tracked. CulinaryOps is the answer to that — not an AI gimmick, just clean data about what's actually happening in your kitchen, in real time.

**For anyone:**
If you run a restaurant, you live and die by three numbers: your food cost, your labor cost, and your waste. Most operators don't know these numbers accurately until it's too late to act on them. CulinaryOps tracks all three in real time, manages your vendors and purchase orders, and surfaces the information you need to make better decisions before the end of the week, not after.

**For developers:**
Next.js 14 PWA. TypeScript. Supabase with RLS. Four internal engine packages: `@culinaryops/labor-engine`, `@culinaryops/food-cost-engine`, `@culinaryops/waste-engine`, `@culinaryops/vendor-engine`. MCP live: `culinaryops-mcp` exposes `get_labor_summary`, `get_food_cost`, `log_waste`, `get_waste_summary`, `list_vendors`, `create_purchase_order`. Standalone — no POS required. Bridges into CulinaryOS AI via `culinaryops-mcp`.

**Who it's for:**
Restaurant owners. General managers. Food & beverage directors. Operations consultants. Anyone responsible for the numbers in a food service business.

## 🧠 MCP Architecture — Every Product Speaks AI

> MCP (Model Context Protocol) is the standard that lets AI tools like Claude call real functions in real applications. Not a chatbot wrapper — actual tool calls against live data. Every product I build ships with its own MCP server so any AI agent can call any function across the entire ecosystem.

```
CulinaryOS AI  ·  Claude via culinaryos-mcp  (master router)
│
├──▶ pos-mcp             fire_order · void_item · split_check · get_open_tickets
├──▶ kds-mcp             bump_ticket · route_station · get_active_tickets · fire_course
├──▶ inventory-mcp       check_par · log_waste · create_purchase_order · get_vendors
├──▶ scheduling-mcp      build_schedule · project_labor_cost · flag_overtime · clock_in
├──▶ ordering-mcp        get_online_orders · update_prep_time · mark_ready · inject_to_kds
├──▶ reservations-mcp    book_table · get_covers_by_shift · get_waitlist · release_table
│
├──▶ kitchenkit-mcp      search_recipes · get_recipe · add_to_meal_plan · get_pantry · get_shopping_list
│                        ↳ KitchenKit (standalone PWA — callable without CulinaryOS)
│
├──▶ culinaryops-mcp     get_labor_summary · get_food_cost · log_waste · list_vendors · create_purchase_order
│                        ↳ CulinaryOps (standalone PWA — callable without CulinaryOS)
│
└──▶ postpilot-mcp       draft_post · schedule_post
                         ↳ Post-Pilot (future bridge — currently standalone Flask SaaS)
```
